## Übersicht

Ein Linux-VPS betreibt meine alltäglichen Dienste und die Backends meiner Nebenprojekte. Jeder Dienst läuft in einem Container, und jede Kategorie hat eine eigene Docker-Compose-Datei. Updates, Rollbacks und Fehlersuche bleiben so getrennt. Massenspeicher liegt auf Remote-Storageboxen statt auf der VPS-Festplatte, damit sich Speicher und Rechenleistung getrennt dimensionieren lassen.

## Routing und TLS

Traefik ist der Reverse Proxy vor allen Diensten. Let's Encrypt stellt die Zertifikate automatisch aus und erneuert sie, HTTP wird auf HTTPS umgeleitet, und HSTS ist für jeden Dienst aktiv.

## Dienste

| Dienst | Zweck |
|---|---|
| **Nextcloud** | Dateisynchronisation und Cloud-Speicher, angebunden an eine Remote-Storagebox |
| **Navidrome** | Musik-Streaming aus der Nextcloud-Musikbibliothek |
| **Matrix / Synapse** | Homeserver für verschlüsseltes Messaging |
| **Element Web** | Web-Client für Matrix |
| **Coturn** | TURN-Server für Sprach- und Videoanrufe über Matrix |

## Entwicklungs-Deployments

Zwei meiner Projekte laufen auf demselben VPS:

- **Schachserver:** das Backend von [The King's Game](/de/projects/chess-engine)
- **Dieses Portfolio:** ein GitHub-Actions-Workflow baut das Image und führt auf dem Server `docker compose pull` und `up -d` aus

## Speicher

Der VPS übernimmt die Verarbeitung, die Remote-Storageboxen halten die Daten: Nextcloud-Dateien und Medienbibliotheken. Der Speicher kann wachsen, ohne dass ein größerer Server nötig wird.
