## Überblick

MinJ (Minimalistic Java) ist eine Skriptsprache, die ich gebaut habe, um von innen zu verstehen, wie ein Interpreter arbeitet. Sie hat Klassen, Methoden, typisierte Variablen, Schleifen, Listen und `return` und läuft auf der JVM. Eine ANTLR4-Grammatik mit 246 Zeilen erzeugt Lexer und Parser, ein `EvalVisitor` mit rund 730 Zeilen durchläuft den Parse-Tree und führt ihn aus, und das Ergebnis wird als einzelnes fat-JAR ausgeliefert, das überall mit Java 21 läuft.

Jede Schicht wollte ich selbst implementieren, statt nur darüber zu lesen: Lexing, Parsing, Scoping, Typprüfung und Methodenaufruf.

## Funktionsweise

Der Quellcode durchläuft drei Stufen:

1. `MinJ.g4` definiert die Grammatik. Der Gradle-Build lässt ANTLR4 daraus `MinJLexer` und `MinJParser` erzeugen.
2. `EvalVisitor` erweitert ANTLRs `MinJBaseVisitor<Object>` und überschreibt eine Methode pro Grammatikregel. Jeder `visit*`-Aufruf durchläuft seinen Teil des Baums und führt ihn aus: Variablenanlage, Arithmetik, Kontrollfluss, Methodenaufruf und Objekterzeugung.
3. `Main.java` liest eine `.mj`-Datei, schickt sie durch Lexer und Parser und ruft `visitor.visit(tree)` auf.

Grammatik und Ausführung sind getrennt: Die `.g4`-Datei legt fest, wie ein MinJ-Programm aussieht, `EvalVisitor`, was es tut. Ein neues Sprachkonstrukt betrifft deshalb diese beiden Dateien.

Die Laufzeit hält jede Variable in einer `Cell` mit Wert, deklariertem Typ, Veränderlichkeit und dem Merkmal, ob sie dynamisch typisiert ist. Eine `return`-Anweisung wirft ein `ReturnSignal`, eine Unterklasse von `RuntimeException`, um den Call-Stack abzubauen. Ein Return funktioniert dadurch auch mitten in verschachtelten Schleifen und Bedingungen. Beim Erzeugen eines Objekts kopiert dieses die Feld-Cells seiner Klasse, sodass jede Instanz einen eigenen Zustand hat.

## Die Sprache

`var` deklariert eine veränderliche, dynamisch typisierte Variable, `val` eine unveränderliche. Explizite Typen sind `int`, `float`, `double`, `boolean`, `char` und `String`. Eine typisierte Deklaration wird bei der Zuweisung geprüft: Ein String in einer `int`-Variable führt zu einem Fehler.

Der Kontrollfluss besteht aus `if`/`elseif`/`else`, `while`, `for i = 1 to n step s` und `foreach x in list`. Blöcke enden mit `end`. Boolesche Operatoren gibt es als Symbole oder Wörter (`&&` oder `and`, `||` oder `or`, `!` oder `not`).

Klassen haben Felder und Methoden, `new` erzeugt eine Instanz. Globale Funktionen nutzen `func`, und ein `return` kann mehrere Werte aufführen. Kommentare beginnen mit `//` oder `#` oder stehen zwischen `/*` und `*/`.

## Beispiele

### FizzBuzz

```minj
val limit = 100
for i = 1 to limit do:
  if i % 15 == 0 then:
    print "FizzBuzz"
  elseif i % 3 == 0 then:
    print "Fizz"
  elseif i % 5 == 0 then:
    print "Buzz"
  else:
    print i
  end
end
```

### Klassen und Methoden

```minj
class Counter:
  var count = 0
  method inc():
    count = count + 1
  end
  method get():
    return count
  end
end

var c = new Counter()
c.inc()
c.inc()
print c.get()   // 2
```

### Rekursive Fakultät

```minj
func factorial(n):
  if n <= 1 then:
    return 1
  end
  return n * factorial(n - 1)
end

print factorial(5)   // 120
```

## Build und Releases

Der Gradle-Build nutzt das ANTLR-Plugin, um Lexer und Parser aus `MinJ.g4` neu zu erzeugen. ShadowJar packt alles, auch die ANTLR-Runtime, in ein fat-JAR. Ein Skript läuft mit `java -jar minjc-<Version>.jar datei.mj`.

Ein GitHub-Actions-Workflow läuft bei Pushes auf Branches mit dem Namen `release-v*`. Er baut das fat-JAR mit JDK 21, packt es zusammen mit den Beispielen und der README in ein Zip, legt ein Release mit der Version aus dem Branch-Namen an und lädt das Zip als Release-Asset hoch. Die Dokumentation steht auf GitHub Pages.

## Die Sprache erweitern

Ein neues Konstrukt erfordert vier Änderungen. So wurde die `while`-Schleife ergänzt:

1. Eine Grammatikregel in `MinJ.g4`:
```antlr
whileStmt : WHILE expr DO COLON block END ;
```

2. In der Regel `statement` eintragen:
```antlr
statement : varDecl | assign | printStmt | ifStmt | whileStmt ;
```

3. Lexer-Token:
```antlr
WHILE : 'while' ;
DO    : 'do' ;
END   : 'end' ;
```

4. Ein Visitor-Override in `EvalVisitor.java`:
```java
@Override
public Object visitWhileStmt(MinJParser.WhileStmtContext ctx) {
    while ((Boolean) visit(ctx.expr())) {
        visitBlock(ctx.block());
    }
    return null;
}
```

Danach mit `./gradlew clean shadowJar` neu bauen.
